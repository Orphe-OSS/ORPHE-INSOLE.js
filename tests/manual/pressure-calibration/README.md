# 圧力校正値の実機取得テスト

リポジトリ直下で `python3 -m http.server 8765 --bind 127.0.0.1` を実行し、Chrome / Edgeで
<http://localhost:8765/tests/manual/pressure-calibration/> を開きます。追加パッケージは不要です。

1. 充電中のインソールを近くに置き、「接続（自動取得）」からINSで始まる端末を選択します。
2. 自動取得の結果を確認します。既定期限はSDKの2000msです。
3. 「校正値を再取得」で再確認します。再取得期限は既定5000msで変更できます。
4. 切断・再接続でも確認します。2台あれば端末1・2でそれぞれ接続します。
5. 「結果JSONを保存」で端末情報、係数、受信バイト列、取得時間、操作履歴を保存します。

成功条件は6ch（内部番号0〜5）の有効な係数が揃い、`pressure_calibration` に保持されることです。
荷重をかける必要はありません。無荷重で換算値が0でも取得成功とは両立します。
係数の妥当性や荷重精度を測定するテストではありません。

`null` の場合もSDK接続は継続し、換算には既定係数が使われます。通信ログの校正通知（header `0x39`）で
無応答と部分応答を区別してください。充電中のBLE動作やFW対応は実測で確認し、無応答だけで非対応と断定しません。
通常の圧力通知も処理し続けるため、再取得前後でサンプル数が増えるかも確認できます。

自動操作からは `window.pressureCalibrationTest.snapshot()` で保存ボタンと同じJSONを取得できます。
`gotData` は上書きせず、`onRead` の記録処理後に元の処理を呼び、通常の圧力コールバックを維持しています。

## 校正値を手動設定して確認する

実機から取得できなくても、各端末の「テスト係数をセット」を押すと `pressure_calibration` に
6chの計算確認用係数を設定できます。接続は不要です。テストADCが各chで100の場合、
SDKの実際の通知デコード・換算経路を使って荷重 `1,2,3,4,5,6` を確認できます。
このテスト入力は専用インスタンスで処理し、実機のサンプルやシリアル番号には混ぜません。

任意の校正値はJSON欄に6行を入力し、「JSONをセット」で設定します。ch0〜5の順で、
各行は `{ "sensor_index": 0, "func": 1, "coeffs": [0, 0, 0, 0.01, 0] }` の形式です。
`func=1` は4次多項式（係数の順は4次から定数）、`func=0` は `c0 * exp(c1 * ADC) + c2` です。
いずれも有限な係数5個を指定してください。出力はSDKの仕様どおり0以上に制限されます。

接続中なら次の圧力通知から手動係数で荷重表示が更新されます。「SDKで換算確認」は
指定したテストADC（0〜65535の整数6個）を使います。「手動設定解除」で既定係数に戻ります。
接続・校正再取得・切断時も手動値はリセットされます。

これはJavaScriptオブジェクトへの手動設定で、端末へ校正値を書き込む機能ではありません。
画面と保存JSONでは `calibrationSource: manual` として実機取得 (`device`)・既定値 (`default`) と区別します。
計算確認の成功は、実機から校正値を取得できることや荷重測定の精度を示しません。
