# NotebookLM で音声概要（ポッドキャスト）を生成するためのプロンプト集

`SCRIPT.md` を NotebookLM に読ませて音声を作るための、コピペ用プロンプトと手順。

---

## ⚠️ 最初に知っておくべき3つの制約

NotebookLM は**台本を朗読しません**。2人のAIホストが資料を読んで**独自に喋り直します**。
そのため台本をそのまま渡すだけでは意図した内容になりません。制約は3つ。

| 制約 | 内容 | 対処 |
|---|---|---|
| **カスタマイズ欄は最大500文字** | 長い指示は入らない | 本ファイルのプロンプトは全て**290〜320文字**に収めてある |
| **長さ指定（短く/デフォルト/長く）は英語のみ** | 日本語出力では長さを制御できず、**5〜15分程度**に圧縮される | **1章＝1エピソード**に分割する（下記） |
| **1本あたり最大約30分** | 81分の台本は1本に入らない | 同上 |

→ 結論: **`notebooklm/` に章ごとに分割したファイルを用意済み。1章ずつ別のノートブックに入れて、6本のシリーズとして作る。**

---

## 手順

### 1. 出力言語を日本語にする（最重要・忘れると英語になる）
NotebookLM の **設定（Settings）→ 出力言語（Output language）→ 日本語**

### 2. ノートブックを作り、章のファイルを1つ入れる
`experiments/gip-gait-poser/podcast/notebooklm/` の中から、その回の章のファイルだけをアップロード。

| 回 | 投入するファイル | 台本の想定尺 |
|---|---|---|
| **EP1** | `0_オープニング.md` と `1_加速度センサは_加速度_を測っていない.md` の**2つ**（第0章だけでは短すぎるため） | 約10分 |
| **EP2** | `2_姿勢_を数字にする_人体モデルとSMPL.md` | 約10分 |
| **EP3** | `3_センサーを減らす20年_17個から2個へ.md` | 約17分 |
| **EP4** | `4_歩行という現象と、最強の武器ZUPT.md` | 約17分 |
| **EP5** | `5_GIPを読む、そして_その先.md` | 約8分 |
| **EP6** | `6_いま何ができて、何ができないのか.md` | 約19分 |

**補助資料として `NUMBERS.md` も一緒に入れると数字の精度が上がります**（出典と検証済み数値の一覧なので、
ホストが数字を間違えにくくなる）。ただし放送用メモの文言まで喋ってしまうことがあるので、
数字の正確さを優先したい回（EP4・EP6）だけに入れるのがおすすめ。

### 3. 音声概要 → カスタマイズ → 形式は「Deep Dive（詳細解説）」
下のプロンプトを貼り付けて生成。

## プロンプト（コピペ用）

各プロンプトは「**共通部＋その回の指示**」という構造。**そのまま全文をコピペしてください**（500字以内に収めてあります）。

### EP1 ── センサーは何を測っているのか（第0〜1章）

```
資料は2人の対話台本です。台本の流れと数値を忠実に守り、初学者向けに噛み砕いて解説してください。数字は台本のまま正確に述べ、丸めたり創作しないこと。⚠️印は断定せず「報告によれば」と留保を付ける。🔵印は山場なので時間をかけて丁寧に。専門用語は必ず日常語に言い換える。今回は「加速度センサは机の上で1Gを示す」という直感に反する事実から始め、なぜ積分が破綻するかを数字で示すこと。1度の傾き誤差が1秒後に約9cm、10秒後に8.56m、1分後に308mになる点は必ず具体的な数字で述べる。最後は「重力は下しか教えてくれない＝方位だけは誰にも分からない」を結論として強調して終わる。
```

## 1本だけ作りたい場合（全体ダイジェスト）

`SCRIPT.md` 全体を1つのソースとして入れ、これを使う。**81分ぶんが10分前後に圧縮される**ので、
「靴のセンサーだけで全身が分かる」という筋だけが残る前提で使うこと。

```
資料は2人の対話台本です。81分ぶんの内容なので、全部を薄く触れるのではなく次の4点だけに絞って深く語ってください。(1)加速度センサは机の上で1Gを示す＝重力を含んで測っている、(2)1度の傾き誤差が10秒後に8.56mの位置誤差になる、(3)接地ごとに積分をリセットすれば同じ誤差が1.4cmに収まる＝ZUPT、(4)センサーが17個から2個に減った20年は「ユーザーに要求することを減らし、モデルに要求することを増やした」歴史。数字は資料のまま正確に述べ、創作しないこと。初学者向けに日常語で。
```

## うまくいかないときの調整

| 症状 | 対処 |
|---|---|
| **短すぎる／内容が薄い** | プロンプト末尾に「**各トピックを具体的な数字と例を必ず挙げて詳しく展開すること**」を追記（まだ180字ほど余裕あり）。それでも足りなければ章をさらに半分に割る |
| **数字を間違える／丸める** | その回のソースに `NUMBERS.md` を追加する。プロンプトの「数字は台本のまま正確に」を先頭に移動 |
| **英語になる** | 設定の出力言語が日本語になっていない。カスタマイズ欄に英語を混ぜると引っ張られることがあるので、プロンプトは全て日本語で書く |
| **未検証の話を断定する** | 該当箇所は元台本の⚠️印。プロンプトの⚠️の指示を「**⚠️印の内容は『まだ確認が取れていないが』と前置きしてから述べる**」に強める |
| **雑談が多く本題が薄い** | 形式を「Deep Dive」にする。「雑談や前置きを最小限にし、内容の解説に時間を使う」を追記 |
| **ORPHE社内の話まで喋る** | `NUMBERS.md` を外す（放送前確認メモが入っているため）。EP6は特に注意 |

## 公開前チェック（EP6は必須）

生成音声を必ず一度通しで聞き、次を確認すること。

1. **⚠️印の項目を断定していないか** — 特に GRIP の誤差数値、AIST歩行DBの被験者数（GIP論文の記述である旨）
2. **ORPHE製品の医療機器該当性**について踏み込んだ言い方をしていないか（`NUMBERS.md` の社内確認項目を参照）
3. **6chのCoP**の話が「測れない」と断定的になりすぎていないか（正しくは「絶対値は不可、同一セッション内の相対変化は有効」）
4. 数字の読み間違い（8.56m / 1.4cm / 71% / 12% / 0.22m/s あたりが要注意）
