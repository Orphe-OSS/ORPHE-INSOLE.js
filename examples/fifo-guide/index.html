FIFO Recording + Loss Check

項目 値 意味
最終更新 —

「30秒以内なら絶対に無欠損」ではありません。 端末内バッファは約30秒分ですが、回収が生成に追いつかなければ30秒以内でも古いデータが上書きされ、回復不能な欠損になります。

CSVは正式計測区間（開始〜drain完了）のsampleだけを含みます。

WHY FIFO

RealtimeとFIFOの違い

Realtime（垂れ流し / push）

  • INSOLEが計測したデータをそのまま次々に送ります

FIFO（いったん貯める / pull）

  • 計測データをINSOLE本体にいったん保存します

端末内バッファ 約30秒の根拠

推測値ではなく、SDK実装の定数からの換算です。

src/InsoleFifo.js
  RING_BUFFER_CAPACITY = 1500   // 追従遅れ(lag)の上限として扱う packet 数
  NOTIFY_DATA_NUM      = 4      // 1 serial packet のフレーム数
  decodePacket()                // フレーム間隔は 5 ms

  1 serial packet = 4 frame × 5 ms       =     20 ms
  buffer window   = 1500 packet × 20 ms  = 30,000 ms  ≈ 30 s
  (equivalent: 200 sample/s ÷ 4 = 50 packet/s → 1500 ÷ 50 = 30 s)

30秒以内の短時間計測は計測区間の全体をバッファに保持しやすく、安定した記録に向いています。

HOW IT WORKS

このexampleが使う Toolkit の設定プログラム

buildInsoleToolkit(toolkit, "INSOLE 01", 0, {
  profile: "realtime-full",
  fifo: {
    startupDelayMs: 1000,
    drainTimeoutMs: 5000,
    onSamples(deviceId, samples) { updateLiveCharts(samples); },
    onProgress(info) { updateLag(info.lag); },
    onDataLoss(info) { logLoss(info); }
  }
});
insoles[0].setup();
const session = getInsoleToolkitSession(0);

// FIFO収録を開始（read mode 切替・バッファ消去・再要求はSDKが担当）
await session.startMeasurement({ profile: "fifo-recording", restoreProfile: true });

// drain（未回収データの回収）完了後に resolve する
const result = await session.stopMeasurement();
result.raw.serial;   // { first, last, expected, received, missing, missingRate }

// 正式計測区間だけのCSV
const csv = insoleToolkitMeasurementToCSV(result, "raw");

FIFOのプロトコルは src/InsoleFifo.js と src/InsoleToolkit.js が担当します。
